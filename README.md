# script-merge

Clash 订阅合并服务：以一个机场的完整 Clash 配置为底板，把其他机场和自建的节点并进去，生成新的订阅链接。Go 单二进制，网页管理，Docker 部署。

## 它做什么

```
机场 A（底板）：节点 + 策略组 + 规则 + DNS …  ─┐
机场 B：节点                                    ├─→  机场 A 的完整配置，节点里多了 B 和自建的，
自建节点                                         ─┘    「节点选择」这类包含 A 全部节点的组里也能选到它们
```

策略组和分流规则不用自己维护：沿用底板机场的，每次生成时取它最新的。要微调（加几条规则、把某些节点放进某个组）用 Parser。

## 功能

- **多个订阅组**：每个订阅组选一个底板机场、引用若干节点来源，输出一个订阅链接，互不影响
- **底板原样保留**：底板机场的策略组、规则、rule-providers、proxy-providers、DNS、hosts 等全部照搬。其他来源的节点追加在后面，并加进底板里包含它全部节点的策略组；按地区分的组只换节点名
- **节点来源可共用**：远程订阅（Clash YAML，或 base64 / 明文分享链接），以及手动填写的节点（YAML 或 ss、vmess、trojan、vless、hysteria2 分享链接）。同一个来源可以被多个订阅组引用，链接只填一处
- **节点处理**：每个订阅组对每个来源可以加前缀、按正则保留 / 排除（比如去掉「剩余流量」这类假节点），重名自动加序号。底板的节点被过滤或改名，它的策略组跟着变
- **代理链**：给某个来源指定「前置代理」（底板的策略组或节点），它的节点都经由前置代理连出去（输出为 `dialer-proxy`，需要 mihomo 内核）。例如自建的落地节点经由机场节点
- **节点地址映射**：其他机场用 hosts 把节点地址映射到别的域名时，自动把这部分 hosts 和 fake-ip-filter 一起带上
- **订阅解锁**：可配置「解锁地址」，每次拉取订阅前先访问一次（普通 GET，适用于「访问过某网址才放行」的订阅）
- **CFW Parsers**：支持 `prepend-*` / `append-*` / `mix-*` / `commands` 语法，对最终配置做任意微调
- **缓存与容错**：上游结果按「来源 + 链接 + UA」缓存（默认 5 分钟）；拉取失败时回退到上次成功的结果；底板拉不到或其他情况下没有节点时返回错误而不是空配置，客户端会继续用旧配置
- **上游走代理**：通过环境变量 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` 配置，支持 `socks5://`
- **访问记录**：每个订阅链接最近被谁拉取过（时间、IP、客户端 UA、节点数），陌生 IP 会标出来
- **管理密码**：首次访问时设置，或用环境变量固定

## 部署

```bash
docker compose up -d --build
```

打开 `http://服务器IP:8080`，首次访问设置管理密码。数据保存在 `./data`。

也可以直接运行：

```bash
go build -o script-merge . && ./script-merge
```

登录后左栏底部显示程序版本（悬停可看完整提交号和提交时间），启动日志里也有。在 git 仓库里 `go build` 会自动带上当前提交；`go run .` 显示「开发版」。Docker 构建时拿不到 `.git`，需要的话自己传版本号：

```bash
docker compose build --build-arg VERSION=$(git describe --always --dirty) && docker compose up -d
```

也可以用 `go build -ldflags "-X main.version=v1.2.0"` 指定任意版本号，它优先于提交号。

### 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8080` | 监听端口 |
| `DATA_DIR` | `./data`（镜像内为 `/data`） | 配置与缓存目录 |
| `ADMIN_PASSWORD` | 空 | 设置后以它作为管理密码，网页端不可修改；不设置则首次访问时在网页设置 |
| `HTTP_PROXY` / `HTTPS_PROXY` | 空 | 拉取上游订阅和访问解锁地址时使用的代理，如 `http://192.168.1.2:7890`、`socks5://192.168.1.2:1080`。按上游地址的协议选用：`https://` 的订阅走 `HTTPS_PROXY` |
| `NO_PROXY` | 空 | 不走代理的主机，逗号分隔，如 `localhost,.example.com,10.0.0.0/8` |

服务器直连拉不到上游订阅时，设置代理环境变量即可，所有节点来源共用。启动日志会打印实际生效的代理。指向 `localhost` / `127.0.0.1` 的上游地址永远不走代理；容器里的 `127.0.0.1` 是容器自己，代理开在宿主机上时要填宿主机的局域网 IP。

> 管理页面和订阅链接都是明文 HTTP。暴露到公网时请放在 HTTPS 反向代理（Nginx / Caddy）后面。
> 订阅链接里的令牌等同于密码，泄露后在该订阅组的「本组设置」里重置即可。「本组设置」里的访问记录可以帮你发现泄露。
> 访问记录里的 IP：直接从公网连进来的请求用连接的对端地址；对端是本机或内网地址（说明前面有反向代理）时取 `X-Forwarded-For` 里最靠右的公网地址。反向代理要正确设置这个头。

## 使用

1. 左栏选择一个**订阅组**，或新建（新建时可以直接选底板机场）
2. **节点来源**：先在左栏的「节点来源」页添加机场订阅或手动节点（来源的新建、修改、删除都只在这里，各订阅组共用；这里还能看到每个来源最近一次拉取的结果、流量和到期时间）。再到订阅组的「节点来源」标签页点「添加节点来源」选用。第一个加进来的机场订阅自动成为**底板**，可以在别的机场订阅上点「设为底板」换掉；手动节点不能做底板
3. 按需给各来源设置前缀、只保留 / 排除的正则、前置代理（只影响这个订阅组）
4. 需要微调就写 **Parser**（编辑框下面的「格式化」可以统一缩进，YAML 写错时会提示出错位置）
5. **预览**：点「生成预览」检查结果和警告。预览用的是页面上现在的内容，不需要先保存，也不影响订阅链接；满意之后再点「保存修改」。打开预览页时如果底板已有缓存，会直接用现有缓存展示一份（不请求上游），并列出每个来源缓存的创建时间、过期时间和剩余时间
6. 点右上角「复制订阅链接」，填入客户端

底板必须返回带策略组的完整 Clash 配置。机场按拉取时的 UA 决定返回什么，拿不到时在「全局设置」里换一个 Clash 系客户端的 UA（如 `clash.meta`）。输出始终是 Clash 格式（Stash 可直接使用）。

订阅链接后加 `?refresh=1` 可跳过缓存强制重新拉取上游。

### Parser 示例

```yaml
yaml:
  prepend-rules:
    - DOMAIN,test.com,DIRECT
  commands:
    - dns.enable=false                                   # 覆盖
    - proxy-groups.(🚀 节点选择).proxies+[]proxyNames|家宽  # 把名字带「家宽」的节点追加到这个组
    - proxy-groups.0.proxies.2+DIRECT                    # 在第 1 个策略组的第 3 个位置插入
    - proxies.0-                                         # 删除第 1 个节点
```

Parser 在合并完成之后执行，可以引用本组的全部节点和底板的全部策略组。完整语法见 [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md#cfw-parser)。仅支持 YAML 形式，不支持 CFW 的 JavaScript 形式（`code` / `file` / `remote`）。

## 升级

配置结构有不兼容的变化时，旧配置直接作废（原文件保留为 `data/config.json.bak`），管理密码保留，需要重新添加来源和订阅组。从自建策略组和规则的旧版本（配置版本 7 及以前）升级就是这种情况。
