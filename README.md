# script-merge

Clash 订阅合并服务：把多个订阅的节点合并，套上自己的策略组和规则，生成新的订阅链接。Go 单二进制，网页管理，Docker 部署。

## 功能

- **多个订阅组**：每个订阅组有自己的策略组、规则、Parser 和订阅链接，互不影响
- **节点来源可共用**：远程订阅（Clash YAML，或 base64 / 明文分享链接），以及手动填写的节点（YAML 或 ss、vmess、trojan、vless、hysteria2 分享链接）。同一个来源可以被多个订阅组引用，链接只填一处；各组用自己的前缀和过滤
- **模板**：策略组、规则、Parser 模板在「模板」页新建和编辑，再套用到订阅组（复制一份，之后各改各的）；订阅组里会提示「来自哪个模板、改没改过、模板有没有更新」，可一键重新套用；内置几套常用模板
- **UA 透传或固定**：每个订阅可选择透传客户端的 User-Agent（客户端用什么 UA 拉合并链接，就用什么 UA 拉上游），或使用固定 UA。固定 UA 在全局设置里填写，所有订阅共用（内置主流客户端预设）
- **订阅解锁**：可配置「解锁地址」，每次拉取订阅前先访问一次（普通 GET，适用于「访问过某网址才放行」的订阅）。默认用 Chrome 浏览器的 UA，可在全局设置里修改
- **节点处理**：按来源加前缀、正则保留 / 排除、重名自动加序号
- **策略组**：手动选择 / 自动测速 / 故障转移 / 负载均衡，成员可按正则筛选节点
- **第三方规则**：以 rule-providers 方式引入，内置 blackmatrix7、Loyalsoldier、ACL4SSR、MetaCubeX 预设，也可填任意 URL；另有前置 / 后置自定义规则
- **CFW Parsers**：支持 `prepend-*` / `append-*` / `mix-*` / `commands` 语法，对最终配置做任意微调
- **缓存与容错**：上游结果按「来源 + 实际链接 + 实际 UA」分别缓存（默认 5 分钟），同一 UA 高频拉取不会重复请求上游；拉取失败时只回退到同一链接和 UA 上次成功的结果；全部失败时返回 502 而不是空配置
- **上游走代理**：通过环境变量 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` 配置，支持 `socks5://`
- **导出与导入**：整份配置导出为 JSON（备份、回滚、换服务器），或导出单个订阅组用于分享（不含订阅链接和令牌）
- **访问记录**：每个订阅链接最近被谁拉取过（时间、IP、客户端 UA、节点数），陌生 IP 会标出来
- **管理密码**：首次访问时设置，或用环境变量固定

## 部署

```bash
docker compose up -d --build
```

打开 `http://服务器IP:8080`，首次访问设置管理密码。数据保存在 `./data`。

也可以直接运行：

```bash
go build -o script-merge . && ./script-merge
```

### 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8080` | 监听端口 |
| `DATA_DIR` | `./data`（镜像内为 `/data`） | 配置与缓存目录 |
| `ADMIN_PASSWORD` | 空 | 设置后以它作为管理密码，网页端不可修改；不设置则首次访问时在网页设置 |
| `HTTP_PROXY` / `HTTPS_PROXY` | 空 | 拉取上游订阅和访问解锁地址时使用的代理，如 `http://192.168.1.2:7890`、`socks5://192.168.1.2:1080`。按上游地址的协议选用：`https://` 的订阅走 `HTTPS_PROXY` |
| `NO_PROXY` | 空 | 不走代理的主机，逗号分隔，如 `localhost,.example.com,10.0.0.0/8` |

服务器直连拉不到上游订阅时，设置代理环境变量即可，所有节点来源共用，不能在界面里配置，也不能按来源单独配置。启动日志会打印实际生效的代理。指向 `localhost` / `127.0.0.1` 的上游地址永远不走代理；容器里的 `127.0.0.1` 是容器自己，代理开在宿主机上时要填宿主机的局域网 IP。

> 管理页面和订阅链接都是明文 HTTP。暴露到公网时请放在 HTTPS 反向代理（Nginx / Caddy）后面。
> 订阅链接里的令牌等同于密码，泄露后在该订阅组的「本组设置」里重置即可。「本组设置」里的访问记录可以帮你发现泄露。
> 访问记录里的 IP：直接从公网连进来的请求用连接的对端地址；对端是本机或内网地址（说明前面有反向代理）时取 `X-Forwarded-For` 里最靠右的公网地址。反向代理要正确设置这个头。

## 使用

1. 左栏选择一个**订阅组**，或新建（新建时可以从模板带入策略组和规则）
2. **订阅源**：先在左栏「节点来源」里添加订阅链接或手动节点。订阅链接填机场的 Clash 订阅链接（或分享链接列表），可选择透传 UA 或使用全局设置里的固定 UA；需要先访问某个页面才能拉取的，填写「解锁地址」。然后在订阅组的「订阅源」页点「添加节点来源」选用。订阅组里只是引用：链接、UA 模式属于来源本身，只能在「节点来源」页修改，改一处各组都生效；是否启用、前缀、过滤各组单独设置；从订阅组里移除不会删除来源
3. **策略组 / 规则 / Parser**：直接编辑，或点「套用模板」。模板在左栏「模板」页新建和修改；模板改动后，套用过它的订阅组会提示「模板有更新」，由你决定是否重新套用
4. **预览**：填一个要模拟的客户端 UA，点「生成预览」检查结果和警告
5. 点右上角「复制订阅链接」，填入客户端

输出始终是 Clash 格式（Stash 可直接使用）：UA 透传只决定向上游要节点时用什么身份。

订阅链接后加 `?refresh=1` 可跳过缓存强制重新拉取上游。

### Parser 示例

```yaml
yaml:
  prepend-rules:
    - DOMAIN,test.com,DIRECT
  append-proxies:
    - {name: test, type: http, server: 1.2.3.4, port: 456}
  commands:
    - dns.enable=false                              # 覆盖
    - proxy-groups.0.proxies.2+DIRECT               # 在第 1 个策略组的第 3 个位置插入
    - proxy-groups.(🚀 节点选择).proxies=[]proxyNames|香港  # 用匹配的节点覆盖
    - proxies.0-                                    # 删除第 1 个节点
```

Parser 在节点、策略组、规则都生成之后执行，可以引用本组的全部节点（含手动节点）。完整语法见 [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md#cfw-parser)。仅支持 YAML 形式，不支持 CFW 的 JavaScript 形式（`code` / `file` / `remote`）。

### 备份、迁移与分享

- 「全局设置 → 导出全部配置」得到一个 JSON 文件，包含全部订阅组、节点来源、模板和全局设置（含订阅链接和令牌，不含管理密码，请妥善保管）。改坏了或换服务器时用「从文件导入」恢复，客户端里的订阅链接不用改。旧版本的 `config.json` 也可以直接导入
- 「本组设置 → 导出这个订阅组」得到用于分享的文件：只有策略组、规则、Parser 和来源的名称等结构，**不含**订阅链接、解锁地址、手填的节点和令牌。别人导入后会新增一个订阅组，把自己的订阅链接填进去即可

## 升级

配置结构变化时会在启动时自动迁移，迁移前的文件保留为 `data/config.json.bak`。
