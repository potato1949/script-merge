# 后续版本开发方向

分两档：「暂缓」是有价值但目前不急的，有实际需要再提上来；「明确不做」是已确认的取舍。每项标了大致工作量（小 = 半天内，中 = 一两天，大 = 需要先做设计）。

实现细节和现有架构见 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 暂缓（有需要再说）

### 访问记录的后续（小）

访问记录目前只在「本组设置」里列出最近 100 次拉取，并标出此前没出现过的 IP；各来源最近一次拉取上游的结果在「节点来源」页。可以再做：把来源的失败历史落盘（现在只在内存里）；按客户端（UA）汇总「上次更新时间」，一眼看出哪个设备很久没更新；陌生 IP 出现时主动通知（需要先有通知渠道）。

### 后台定时刷新（中）

现在只有客户端来拉订阅时才去拉上游，缓存过期后的第一个请求要等所有上游返回。可以按间隔在后台预先刷新缓存；透传 UA 的订阅只刷新近期实际来拉过的「链接 + UA」组合。目前感觉收益不大。

### 节点列表与筛选预览（中）

调「只保留 / 排除」正则和策略组筛选正则时，只能生成整份预览再去 YAML 里找。可以在节点来源展开后查看节点列表，正则输入框旁实时显示命中数量和节点名。策略组模板、规则模板在「模板」页编辑时没有节点可参考，也可以借这个功能选一个订阅组来试。

### 节点改名与排序（中）

每个来源可配置改名规则（正则替换）和排序方式。改名在过滤之后、加前缀之前执行。

### 来源级的过滤与停用（小）

「只保留 / 排除」现在只在引用（`SourceRef`）上。其中「清掉过期提醒、官网地址这类假节点」其实是来源自己的属性，三个订阅组共用一个机场就要填三遍。可以在来源上加「始终排除」，以及整体停用的开关（机场到期时不用逐组取消勾选或删除）。这些只影响拉到之后怎么用，不进缓存键。

### 规则页就地校验策略名（小）

规则集的策略已经是下拉选择，指向不存在的策略组时标成「⚠ 名字（本组没有）」。前置 / 后置规则文本框里的策略名还只在预览的警告里才看得到；套用规则模板时也可以当场提示缺哪些策略组（前端已有 `policyNames`）。

### 大规则集的折中（中）

规则集现在全部平铺。MetaCubeX 的 geosite-cn、blackmatrix7 的 ChinaMax 这类一个就有十万条以上，平铺后配置有好几 MB（Loyalsoldier 因此已经去掉）。真有需要时可以让超过一定条数的规则集改为输出 rule-provider：类型按内容自动判断，下载地址指向本服务（带订阅令牌），客户端从本服务下载整理好的文件，不用访问 GitHub。

### 按规则仓库批量重写规则集地址（小）

规则集存的是完整地址，和规则仓库无关。`raw.githubusercontent.com` 要换镜像、仓库换分支时，得到每个订阅组和模板里逐条改。可以在「规则仓库」页提供「把已添加的规则集地址按当前地址模板重新生成」，列出会改哪些再确认。

### 单组导入时对应到已有来源（小）

导入别人分享的订阅组时，带来的来源总是新建成空壳。可以在导入后让用户逐个选择「对应到已有的来源」或「新建并填链接」。

### 保存前说明影响范围（小）

未保存状态是全局的，一次保存可能同时包含节点来源、模板和多个订阅组的修改。可以在保存按钮旁写明这次保存涉及什么、影响几个订阅组。

### 基础配置按订阅组覆盖（中）

基础配置（端口、DNS 等）是全局的，一个组给路由器用、一个给手机用时只能靠 Parser 改。可以让订阅组带一份覆盖项。

### 每个订阅组多个令牌（中）

现在一个订阅组的所有设备共用一个令牌，发现泄露后重置，所有设备都要重新配置。可以按设备发令牌、单独吊销；访问记录也能按令牌区分设备。

### 更灵活的解锁步骤（中）

解锁目前只是一次 GET，现有上游够用。如果以后遇到需要 POST、带 Referer 或连续访问几个地址的放行页，再改成可配置的请求序列，先确认实际行为再定范围，避免做成通用爬虫。

### 远期方向（大，需要先做设计）

- **输出非 mihomo 系客户端的格式**（Loon 等）：目前只输出 Clash，Stash 可直接使用。方向已定为「上游统一按 Clash 格式拉取，输出时加渲染器转换」，要做的事项见 [CLIENT-SUPPORT.md](CLIENT-SUPPORT.md)。
- **节点可用性检测**：服务器所处网络和客户端不同，服务端测得通不代表客户端能用。可能更适合只做「上游返回的节点数异常变少」这类粗粒度告警。
- **多用户**：需要账号体系和权限隔离，会把个人工具变成小型服务，等有明确需求再考虑。

### 工程与安全

- **验证 Docker 构建**（小）：`Dockerfile` 写好后还没有实际构建过。
- **界面自动化测试**（中）：现在只靠截图人工检查。用无头浏览器跑几条主流程（新建订阅组、套用模板、保存、预览）。
- **会话持久化**（小）：会话存在内存里，重启服务要重新登录。
- **登录保护**（小）：目前只有全局的 1 秒延迟，没有按 IP 限流或锁定。公网部署时值得加。
- **限制服务端访问内网地址**（小）：订阅链接和解锁地址可以填任意 http(s) 地址。公网部署时应拒绝内网和回环地址。
- **清理失效缓存**（小）：节点来源被删除或改了链接后，旧缓存文件留在磁盘上，只在同一来源的缓存超过上限时才被淘汰。
- **上游代理的界面配置 / 按来源配置**（中）：目前只认环境变量 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`，所有来源走同一个代理。有「部分机场要走代理、部分要直连且没法用 `NO_PROXY` 表达」的实际需要再做；做的话代理地址要进 `cacheKey`。

## 明确不做

- **CFW Parser 的 JavaScript 形式**（`code` / `file` / `remote`）：需要在服务端执行任意脚本，安全风险和维护成本都高，YAML 形式已覆盖绝大多数用途。
- **模板的引用语义**（改模板自动影响所有套用过的订阅组）：已确认采用复制语义。改一处牵动多处容易出意外，「差异提示」可以解决大部分同步需求。
- **跨 UA 的缓存回退**：已确认某个 UA 拉取失败就是失败，不借用其他 UA 的结果。
- **按地区自动生成策略组**：各机场的节点命名差异很大，自动识别不可靠；现有「按地区分组」模板够用，缺的地区手动加。
