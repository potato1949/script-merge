# 后续版本开发方向

分两档：「暂缓」是有价值但目前不急的，有实际需要再提上来；「明确不做」是已确认的取舍。每项标了大致工作量（小 = 半天内，中 = 一两天，大 = 需要先做设计）。

实现细节和现有架构见 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 暂缓（有需要再说）

### 按来源设置拉取 UA（小）

现在全局只有一个拉取 UA。机场按 UA 返回不同内容，如果某个机场要用特定 UA 才给完整配置、另一个机场又不认这个 UA，就没法同时满足。可以给 `Source` 加一个可选的 UA（空则用全局的），要进 `cacheKey`。

### 选择其他节点加进哪些策略组（中）

其他来源的节点现在只加进「包含底板全部节点」的策略组。想放进别的组（比如按地区的组）只能写 Parser。可以在订阅组里勾选底板的策略组（候选取自 `SourceState.Groups`），生成时把其他节点也加进去；底板改了组名时要提示。

### 节点列表与筛选预览（中）

调「只保留 / 排除」正则时，现在要生成预览后在预览页看每个来源留下、过滤掉了哪些节点。可以在正则输入框旁实时显示命中数量和节点名，不用来回切标签页。

### 节点改名与排序（中）

每个来源可配置改名规则（正则替换）和排序方式。改名在过滤之后、加前缀之前执行。

### 来源级的过滤与停用（小）

「只保留 / 排除」现在只在引用（`SourceRef`）上。其中「清掉过期提醒、官网地址这类假节点」其实是来源自己的属性，三个订阅组共用一个机场就要填三遍。可以在来源上加「始终排除」，以及整体停用的开关。这些只影响拉到之后怎么用，不进缓存键。

### 访问记录的后续（小）

可以再做：把来源的失败历史落盘（现在只在内存里）；按客户端（UA）汇总「上次更新时间」，一眼看出哪个设备很久没更新；陌生 IP 出现时主动通知（需要先有通知渠道）。

### 后台定时刷新（中）

现在只有客户端来拉订阅时才去拉上游，缓存过期后的第一个请求要等所有上游返回。可以按间隔在后台预先刷新缓存。目前感觉收益不大。

### 每个订阅组多个令牌（中）

现在一个订阅组的所有设备共用一个令牌，发现泄露后重置，所有设备都要重新配置。可以按设备发令牌、单独吊销；访问记录也能按令牌区分设备。

### 更灵活的解锁步骤（中）

解锁目前只是一次 GET，现有上游够用。如果以后遇到需要 POST、带 Referer 或连续访问几个地址的放行页，再改成可配置的请求序列，先确认实际行为再定范围，避免做成通用爬虫。

### 远期方向（大，需要先做设计）

- **输出非 mihomo 系客户端的格式**（Loon 等）：目前只输出 Clash，Stash 可直接使用。方向见 [CLIENT-SUPPORT.md](CLIENT-SUPPORT.md)。
- **节点可用性检测**：服务器所处网络和客户端不同，服务端测得通不代表客户端能用。可能更适合只做「上游返回的节点数异常变少」这类粗粒度告警。
- **多用户**：需要账号体系和权限隔离，会把个人工具变成小型服务，等有明确需求再考虑。

### 工程与安全

- **验证 Docker 构建**（小）：`Dockerfile` 写好后还没有实际构建过。
- **界面自动化测试**（中）：现在只靠临时脚本走查。把「在节点来源页新建来源 → 订阅组选用并选底板 → 预览 → 保存」这条主流程的 CDP 脚本收进仓库。
- **会话持久化**（小）：会话存在内存里，重启服务要重新登录。
- **登录保护**（小）：目前只有全局的 1 秒延迟，没有按 IP 限流或锁定。公网部署时值得加。
- **限制服务端访问内网地址**（小）：订阅链接和解锁地址可以填任意 http(s) 地址。公网部署时应拒绝内网和回环地址。
- **清理失效缓存**（小）：节点来源被删除或改了链接后，旧缓存文件留在磁盘上，只在同一来源的缓存超过上限时才被淘汰。
- **上游代理的界面配置 / 按来源配置**（中）：目前只认环境变量，所有来源走同一个代理。有实际需要再做；做的话代理地址要进 `cacheKey`。

## 明确不做

- **自己维护策略组和规则**（策略组编辑器、第三方规则集、规则仓库、模板）：v8 重构时去掉了。两套方案并存让项目和使用都变得混乱，确定只以机场配置为底板，微调靠 Parser。实现存档在 `archive/follow-mixed` 分支。
- **服务端平铺规则集**：底板的 `rule-providers` 原样输出，由客户端下载。
- **全局基础配置**：端口、DNS 等用底板的，要改用 Parser。
- **透传客户端 UA 拉上游**：底板需要完整的 Clash 配置，透传非 Clash 客户端的 UA 只会拿到别的格式。
- **历史版本、导出导入**：v8 重构时去掉了。备份直接拷贝 `DATA_DIR`。
- **配置迁移**：结构不兼容时旧配置直接作废（保留备份和管理密码），不写迁移代码。
- **CFW Parser 的 JavaScript 形式**（`code` / `file` / `remote`）：需要在服务端执行任意脚本，安全风险和维护成本都高，YAML 形式已覆盖绝大多数用途。
- **跨 UA 的缓存回退**：已确认某个 UA 拉取失败就是失败，不借用其他 UA 的结果。
