# 后续版本开发方向

分两档：「暂缓」是有价值但目前不急的，有实际需要再提上来；「明确不做」是已确认的取舍。每项标了大致工作量（小 = 半天内，中 = 一两天，大 = 需要先做设计）。

实现细节和现有架构见 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 暂缓（有需要再说）

### 访问记录的后续（小）

访问记录目前只在「本组设置」里列出最近 100 次拉取，并标出此前没出现过的 IP。可以再做：按客户端（UA）汇总「上次更新时间」，一眼看出哪个设备很久没更新；陌生 IP 出现时主动通知（需要先有通知渠道）。

### 后台定时刷新（中）

现在只有客户端来拉订阅时才去拉上游，缓存过期后的第一个请求要等所有上游返回。可以按间隔在后台预先刷新缓存；透传 UA 的订阅只刷新近期实际来拉过的「链接 + UA」组合。目前感觉收益不大。

### 节点列表与筛选预览（中）

调「只保留 / 排除」正则和策略组筛选正则时，只能生成整份预览再去 YAML 里找。可以在订阅源展开后查看节点列表，正则输入框旁实时显示命中数量和节点名。策略组模板、规则模板在「模板」页编辑时没有节点可参考，也可以借这个功能选一个订阅组来试。

### 节点改名与排序（中）

每个来源可配置改名规则（正则替换）和排序方式。改名在过滤之后、加前缀之前执行。

### 订阅状态一览（小）

剩余流量和到期时间已经从上游拿到了（`Subscription-Userinfo`），但只透传给了客户端。可以在订阅源行上显示已用 / 总流量、到期日期、上次成功拉取时间。

### 更灵活的解锁步骤（中）

解锁目前只是一次 GET，现有上游够用。如果以后遇到需要 POST、带 Referer 或连续访问几个地址的放行页，再改成可配置的请求序列，先确认实际行为再定范围，避免做成通用爬虫。

### 远期方向（大，需要先做设计）

- **输出非 mihomo 系客户端的格式**（Loon 等）：目前只输出 Clash，Stash 可直接使用。方向已定为「上游统一按 Clash 格式拉取，输出时加渲染器转换」，要做的事项见 [CLIENT-SUPPORT.md](CLIENT-SUPPORT.md)。
- **节点可用性检测**：服务器所处网络和客户端不同，服务端测得通不代表客户端能用。可能更适合只做「上游返回的节点数异常变少」这类粗粒度告警。
- **多用户**：需要账号体系和权限隔离，会把个人工具变成小型服务，等有明确需求再考虑。

### 工程与安全

- **验证 Docker 构建**（小）：`Dockerfile` 写好后还没有实际构建过。
- **界面自动化测试**（中）：现在只靠截图人工检查。用无头浏览器跑几条主流程（新建订阅组、套用模板、保存、预览）。
- **会话持久化**（小）：会话存在内存里，重启服务要重新登录。
- **登录保护**（小）：目前只有全局的 1 秒延迟，没有按 IP 限流或锁定。公网部署时值得加。
- **限制服务端访问内网地址**（小）：订阅链接和解锁地址可以填任意 http(s) 地址。公网部署时应拒绝内网和回环地址。
- **清理失效缓存**（小）：节点来源被删除或改了链接后，旧缓存文件留在磁盘上，只在同一来源的缓存超过上限时才被淘汰。
- **上游代理的界面配置 / 按来源配置**（中）：目前只认环境变量 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`，所有来源走同一个代理。有「部分机场要走代理、部分要直连且没法用 `NO_PROXY` 表达」的实际需要再做；做的话代理地址要进 `cacheKey`。

## 明确不做

- **CFW Parser 的 JavaScript 形式**（`code` / `file` / `remote`）：需要在服务端执行任意脚本，安全风险和维护成本都高，YAML 形式已覆盖绝大多数用途。
- **模板的引用语义**（改模板自动影响所有套用过的订阅组）：已确认采用复制语义。改一处牵动多处容易出意外，「差异提示」可以解决大部分同步需求。
- **跨 UA 的缓存回退**：已确认某个 UA 拉取失败就是失败，不借用其他 UA 的结果。
- **按地区自动生成策略组**：各机场的节点命名差异很大，自动识别不可靠；现有「按地区分组」模板够用，缺的地区手动加。
